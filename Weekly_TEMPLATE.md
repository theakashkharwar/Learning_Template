# Weekly Skill Training Template

Purpose: use the same weekly training pattern repeatedly while the selected topics change according to the roadmap.

This file trains how you learn and retain skills. It does not choose the long-term topic order, create an hourly daily schedule, or replace the topic-learning template.

Use the system like this:

```text
X_MONTH_ROADMAP.md chooses what should be learned.
Weekly_TEMPLATE.md repeatedly trains new and older skills.
TOPIC_LEARNING_TEMPLATE.md expands one selected topic when needed.
PROGRESS_TRACKER_TEMPLATE.md measures the result and identifies weak skills.
```

The weekly pattern stays stable. Only the topics, exercises, difficulty, and independence target change.

## Core Training Rule

A skill is not retained because you read the notes again. It is retained when you repeatedly retrieve, apply, explain, and transfer it with decreasing assistance.

Every active training day must therefore contain:

1. an attempt before opening notes
2. active recall or practical performance
3. correction after the attempt
4. a second attempt with less assistance
5. evidence and a pass/fail result

## Weekly Skill Buckets

Select skills from these four buckets before each week begins.

### New

The current skill or topic assigned by the roadmap.

Examples:

- a vulnerability category
- a programming concept
- a tool workflow
- an analysis method
- a project capability

### Recent

Skills first learned during the previous two weeks. These need retrieval before they become stable.

### Weak

Skills that were failed, forgotten, confused with another skill, or completed only with excessive hints or notes.

### Maintenance

Older skills that were previously passed but are due for long-term review.

Use this selection card:

```text
Current roadmap phase:
Week number and dates:
New skill:
Recent skills:
Weak skills:
Maintenance skills due:
Last week's most important failure:
Required public or portfolio artifact:
```

## Independence Score

Score practical independence from 0 to 5.

```text
0 = I cannot recognize or describe the skill.
1 = I can perform only with complete notes or a solution.
2 = I can perform with several hints or partial notes.
3 = I can complete a familiar task without notes.
4 = I can complete an unfamiliar variation independently.
5 = I can teach, transfer, and document the skill clearly.
```

Do not raise the score because a concept feels familiar. Raise it only after observable performance.

## No-Notes And Hint Protocol

Use this protocol whenever retrieving or practicing an existing skill.

1. Close notes, videos, walkthroughs, and solutions.
2. Blurt the concept, workflow, or likely solution from memory.
3. Attempt the exercise independently.
4. If blocked, identify the exact missing step before requesting help.
5. Use the smallest possible cue.
6. Close the cue and restart the failed section from memory.
7. Record the assistance level and failure pattern.

Hint levels:

```text
0 = No hint.
1 = A small directional cue.
2 = A concept or documentation reference.
3 = A partial procedure or solution step.
4 = A complete walkthrough or solution.
```

A task completed with Hint Level 3 or 4 is not an independent pass. Put the skill in the Weak bucket and retest it later without the solution.

## Learning Methods Used

### Feynman Technique

Explain the skill from memory in simple language. Locate the part that becomes vague, repair that gap, and explain it again without hiding behind terminology.

Primary use: Saturday explanation and publication, with shorter explanations during the week.

### Blurting

Write or speak everything you can recall before consulting notes. Then compare the result with trusted material and mark omissions or false memories.

Primary use: Wednesday retrieval, Thursday strengthening, and Sunday light review.

### Spaced Repetition

Schedule retrieval approximately 1, 3, 7, 14, and 30 days after first learning. Use the nearest compatible weekly review slot rather than forcing an exact date.

If recall succeeds independently, move to the next interval. If it fails, return the skill to the Weak bucket and restart with a short interval.

### Parkinson's Law

Before beginning an exercise, define a hard boundary for the attempt and the exact evidence required. Do not expand one task until it consumes the whole session.

This template does not prescribe hourly timestamps. The learner chooses a realistic boundary based on the available session and stops or escalates according to the predefined rule.

### Second Brain

Use notes as a compressed external system, not as a transcript of everything consumed.

```text
Capture during practice: evidence, mistakes, decisions, and unanswered questions.
Distill on Saturday: definition, workflow, cues, common failures, proof, and reusable checklist.
Organize on Sunday: connect related skills, schedule reviews, and archive low-value material.
```

### Energy Classes

Match the type of work to available mental energy.

```text
High energy: unfamiliar concepts, independent problem solving, pressure tests, and difficult variants.
Medium energy: guided repetitions, explanation, report writing, building, and correction.
Low energy: organizing evidence, flash recall, review scheduling, proofreading, and tracker updates.
```

Keep the weekday's training function fixed. Place its most demanding set inside the part of the day when your energy is strongest.

### Interleaving

Mix exercises from different skills without labeling the correct technique. This trains recognition and method selection instead of memorizing a lab sequence.

Primary use: Friday transfer training.

## Fixed Weekly Split

Use six active training days and one light recovery day.

### Monday - Acquire

**Allocation:** 100% new skill  
**Energy:** high  
**Purpose:** create the first correct mental model and practical experience.

Training sets:

1. Define what successful performance looks like by the end of the week.
2. Learn the normal system, workflow, or first principles behind the new skill.
3. Explain the initial model in simple language without copying the source.
4. Complete the first guided practical example.
5. Close the guide and reproduce the important part from memory.
6. Record the first evidence, confusion, and likely failure points.

Required output:

- one-page mental model
- first practical evidence
- list of gaps to test on Tuesday

Pass condition:

- explain the normal workflow in your own words
- identify the important inputs, decisions, or steps
- reproduce the basic example with no more than one small cue

### Tuesday - Drill

**Allocation:** 100% new skill  
**Energy:** high to medium  
**Purpose:** turn initial understanding into repeatable execution.

Training sets:

1. Reconstruct Monday's workflow before opening notes.
2. Repeat one guided exercise.
3. Close the guide and perform a comparable exercise independently.
4. Change one condition, input, or requirement and repeat.
5. Maintain an error log containing the failed step, cause, correction, and retry result.

Required output:

- multiple completed repetitions
- corrected error log
- updated independence score

Pass condition:

- complete a familiar exercise without full notes
- explain why the procedure works
- successfully retry every corrected failure

### Wednesday - Retrieve

**Allocation:** 50% new skill and 50% recent skill  
**Energy:** medium  
**Purpose:** strengthen recall and stop the newest learning from replacing recent knowledge.

Training sets:

1. Blurt the new skill from memory.
2. Blurt one Recent-bucket skill without seeing its name-specific checklist.
3. Reconstruct both workflows on a blank page.
4. Complete one practical retrieval task for each skill.
5. Compare the attempts with trusted notes only after finishing.
6. Correct omissions and repeat the failed part without notes.

Required output:

- two closed-book recall sheets
- practical evidence for both skills
- note-dependency and hint-level record

Pass condition:

- retrieve the essential workflow for both skills
- perform a basic task for each without a walkthrough
- correctly identify what was forgotten or confused

### Thursday - Strengthen

**Allocation:** 100% older skill  
**Energy:** medium to high  
**Purpose:** repair a weak skill or maintain one that is due for spaced review.

Selection order:

1. failed Weak-bucket skill
2. overdue maintenance skill
3. skill due near its 7-, 14-, or 30-day interval

Training sets:

1. Attempt a closed-book explanation or workflow reconstruction.
2. Complete a familiar practical task without notes.
3. Isolate the weakest step.
4. Review only that step.
5. Restart the failed section from memory.
6. Complete one variation that changes the context or input.

Required output:

- before-and-after recall comparison
- practical retry evidence
- updated next-review date

Pass condition:

- reach Independence Score 3 or higher
- finish with Hint Level 0 or 1
- explain the previous failure and its correction

### Friday - Transfer

**Allocation:** 40% new skill and 60% older skills  
**Energy:** high  
**Purpose:** recognize and apply skills when the correct method is not announced.

Training sets:

1. Select the current new skill and at least two due older skills.
2. Randomize or hide the skill labels on the exercises.
3. Set a hard completion boundary before starting.
4. For each exercise, identify the relevant signals and choose the method.
5. Complete an unfamiliar variation, mixed challenge, simulation, or case.
6. Explain why the chosen method was appropriate and why alternatives were rejected.

Required output:

- mixed-practice result
- method-selection reasoning
- list of recognition errors

Pass condition:

- identify the correct approach without being told the topic
- complete the defined challenge with no more than one small cue
- distinguish at least one confusingly similar skill

### Saturday - Explain And Produce

**Allocation:** 70% new skill and 30% older skills  
**Energy:** medium  
**Purpose:** consolidate the week through teaching, connection, and public proof of work.

Training sets:

1. Give a Feynman explanation of the new skill from a blank page.
2. Connect it to at least one older skill, prerequisite, or failure pattern.
3. Build the required report, project, case study, writeup, demonstration, or portfolio artifact.
4. Include practical evidence, mistakes, corrections, and limitations.
5. Fact-check the explanation and reproduce important evidence.
6. Distill the reusable knowledge into the Second Brain.
7. Publish only if the artifact is accurate, safe, and permitted.

Required output:

- one finished public or portfolio artifact
- one distilled reusable note
- revised independence score for the new skill

Pass condition:

- explain the skill clearly without hiding gaps behind jargon
- support the explanation with verified practical evidence
- show how the skill connects to older knowledge
- pass all safety, privacy, copyright, and disclosure checks

### Sunday - Recover And Review

**Allocation:** light review only; excluded from the 60/40 active-day calculation  
**Energy:** low  
**Purpose:** allow recovery while keeping the review system accurate.

Recovery sets:

1. Perform short recall for only the skills currently due.
2. Update each skill's score, bucket, failure pattern, and next-review date.
3. Update `PROGRESS_TRACKER_TEMPLATE.md`.
4. Organize and link the week's distilled Second Brain notes.
5. Select next week's New, Recent, Weak, and Maintenance skills.
6. Choose exactly one progressive-overload variable for next week.
7. Stop. Do not begin heavy new learning.

Required output:

- updated spaced-review queue
- completed weekly tracker
- next week's skill selection card

Pass condition:

- every failed skill has a retest date
- every passed skill has a next-review date
- next week can begin without making new scheduling decisions

## Allocation Check

Treat each active day as one equal training unit:

```text
New skill units:
Monday 1.0 + Tuesday 1.0 + Wednesday 0.5 + Thursday 0.0 + Friday 0.4 + Saturday 0.7 = 3.6

Older skill units:
Monday 0.0 + Tuesday 0.0 + Wednesday 0.5 + Thursday 1.0 + Friday 0.6 + Saturday 0.3 = 2.4

Total active units = 6.0
New skill = 3.6 / 6.0 = 60%
Older skills = 2.4 / 6.0 = 40%
```

Sunday is a recovery and administration day, so its light recall does not change the active training ratio.

## Spaced-Review Queue

Maintain one row per learned skill.

```text
Skill:
Date first learned:
Last retrieval date:
Current interval: 1 / 3 / 7 / 14 / 30 / monthly maintenance
Next review date:
Current independence score:
Last hint level:
Failure pattern:
Best evidence:
Bucket: New / Recent / Weak / Maintenance
```

Review rules:

- Pass independently: move to the next interval.
- Pass with Hint Level 1 or 2: keep the current interval and retest.
- Require Hint Level 3 or 4: move to Weak and use a short interval.
- Pass an unfamiliar variation at Independence Score 4: move toward monthly maintenance.
- Reach Score 5 once: keep occasional maintenance; one success does not make the skill permanent.

## Progressive Overload

Choose only one primary overload variable each week so the cause of improvement or failure remains visible.

Options:

- use fewer notes
- use fewer hints
- solve a harder variation
- mix more similar skills
- reduce the allowed completion boundary
- use a less familiar context
- improve evidence or report quality
- explain the skill to a less technical audience
- perform under controlled CTF, interview, or simulation pressure

Do not increase every variable at once. If the weekly independence score falls, hold or reduce difficulty and repair the failed skill.

## Weekly Success Standard

The week passes only when:

- the new skill reaches at least Independence Score 3
- at least one Recent skill is retrieved without a walkthrough
- at least one Weak or Maintenance skill is strengthened
- mixed practice tests recognition, not only repetition
- all Hint Level 3-4 completions are scheduled for retesting
- one verified artifact is completed
- the spaced-review queue and progress tracker are updated

## Cybersecurity Example

Example only; the weekly structure works for other domains.

```text
New skill: IDOR and object-level authorization
Recent skill: session handling
Weak skill: distinguishing authentication from authorization failures
Maintenance skill: HTTP request reconstruction in Burp Repeater

Monday: map normal object access and complete the first authorized lab.
Tuesday: repeat access-control tests and vary identifiers or user roles in labs.
Wednesday: blurt IDOR and sessions, then complete one closed-book task for each.
Thursday: repair the authentication-versus-authorization weakness without notes.
Friday: solve unlabeled mixed web labs and justify which security check is missing.
Saturday: write a sanitized lab report or educational article with verified evidence.
Sunday: update scores, review dates, tracker, and next week's skill buckets.
```

For cybersecurity work, use only legal labs, owned systems, CTFs, or explicitly authorized targets. Respect scope and writeup policies. Redact credentials, tokens, cookies, personal information, flags, private URLs, and unresolved live-target findings before creating public artifacts.

- Every active day must include an attempt before notes, practical performance, correction, and a retry.
- Notes and walkthroughs may be opened only after an honest retrieval or solution attempt.
- Any task requiring Hint Level 3 or 4 is a failed independent attempt and must enter the Weak bucket.
- Select exactly one progressive-overload variable for the week.
- Match high-energy tasks to acquisition, difficult independent work, or pressure testing; medium-energy tasks to drills, explanation, and artifact production; low-energy tasks to light recall and organization.
- Public work must be based on verified practical evidence and must obey all privacy, copyright, safety, authorization, and disclosure constraints.

  - closed-book starting attempt

- Give one objective pass condition and one failure condition for every day.

- Test whether the new skill reached at least Independence Score 3.
